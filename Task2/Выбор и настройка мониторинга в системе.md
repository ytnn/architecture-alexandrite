# Выбор и настройка мониторинга в системе

## 1. Мотивация

Компания сталкивается с потерей и задержкой заказов, перегрузкой MES и нагрузкой со стороны партнеров по API. Отсутствие мониторинга не повзоляет:

- диагностировать возможные проблемы: потерю сообщений в RabbitMQ или рост времени отклика MES
- прогнозировать узкие места: рост БД, переполнение очередей, утизизацию CPU
- своевременно реагировать на инциденты, которые приводят к простоям продаж и снижению лоялбности клиентов.

Внедрение мониторинга позволит устранить вышеперечисленные недостатки и позволит бизнесу ускорить принятие решений по доработкам и находить неиспользуемый функционал для оптимизации ресурсов и затрат на облако.

## 2. Выбор подхода к мониторингу

RED  для API и RabbitMQ (Shop API, CRM API, MES API), чтобв видеть скорость обработки запросов, ошибки и задержки.

USE для БД и MES, чтобы отслеживать использование ресурсов.

## 3. Опишите, какие метрики и в каких частях системы вы будете отслеживать

**RabbitMQ**

- Number of dead-letter-exchange letters in RabbitMQ
> Показывает количество ошибок в обработке сообщений
> 
> Ярлыки: имя очереди

- Number of message in flight in RabbitMQ
> Если растет количество - значит система не справляется с обработкой сообщений, MES не успевает обработать заказы
>
>Ярлыки: имя очереди


**Все API (Shop, CRM, MES)**

- Number of requests (RPS)
>Для оценки нагрузки на сервсы.
>
>Ярлыки: http-метод, endpoint.

- Response time (latency)
>Для оценки задержки ответов.
>
>Ярлыки: http-метод, endpoint.

- Number of HTTP 500
>Для анализа количества оишбок
>
>Ярлыки: http-метод, endpoint

- CPU % и Memory Utilisation
>Для определения загружеенности виртуальных машин, для автоматического масштабирования, для обнаружения зацикливаний
>
>Ярлыки: инстанс приложения


**Shop DB и MES DB**

- Memory Utilisation
>Рост может подсвечивать необходимость оптимизации тяжёлых запросов, нехватку ресурсов, необходимость построения индексов

- Size of DB instance
>Прогнозирование роста БД и таблиц, планирование увелечения размеров БД и шардирования


**Хранилище S3**

- Size of S3 storage
>Для панирования затрат на хранение, оптимизацию и удаление неиспользуемых моделей.
